# Agent 定时提交 fallback

仅当请求结构通过 [钉钉官方 API 能力门禁](../../shared/dingtalk-official-api-gate.md)，且用户已确认最终预览时使用。默认“日报”保持日期第一并省略无内容的图片、附件。该模式不是钉钉草稿：定时任务运行前，钉钉中没有对应日志。

## 创建一次性任务

使用当前 Agent 客户端提供的定时任务机制，为每个日志日期创建独立的一次性任务。不要用 Windows 任务计划、常驻进程或 UI 自动化代替。

任务应包含不可歧义的完整快照：

- 模式为 `agent-scheduled`；
- 日志日期和 `Asia/Shanghai` 目标执行时间；
- 模板 ID、模板名和完整字段数组；
- 已确认接收人的稳定 userId；
- 运行时必须使用的 DWS Profile 用户和组织；
- 只执行一次，成功、结果不确定或最终失败后停止。

任务名称应包含 `gvOffice`、日志日期和接收人，创建后向用户显示名称或 ID、执行时间及删除入口。正文随定时任务保存；不要再创建 gvOffice 本地任务文件。

创建完成后必须明确提示：

> 当前采用 Agent 定时提交 fallback，不是钉钉原生定时日志。提交前不会出现在钉钉草稿中；请保持电脑和 Agent 客户端运行、DWS 登录有效。若决定不发送，请在执行前删除此定时任务。

如果客户端不能创建真正的一次性任务，可以使用只运行一次的等价计划；任务首次运行后必须自行停用或删除。不得留下会在下一日或下一周期重复提交的活动计划。

## 到点执行

1. 核对当前时间已达到目标时间；提前运行时不得提交。
2. 核对 DWS 当前唯一组织 Profile 与任务快照一致；不一致则停止并通知用户。
3. 使用快照中的模板、完整字段和接收人调用 `dws report entry submit`。不要重新生成、润色或补写正文。
4. 从返回值取得稳定 `reportId`，立即用 `dws report entry get` 读回，核对日志日期、模板、关键正文和接收人。
5. 验证成功后报告已提交，并停用或删除该任务。不要保留可再次触发的计划。

如果电脑休眠、关机或 Agent 未运行，任务是否补跑取决于实际客户端行为，不得预先承诺。任何晚于计划时间启动的运行都必须在结果中说明计划时间和实际提交时间。

## 失败与重复保护

- 明确的认证、Profile、权限、模板或参数错误：不提交或不重试，保留任务运行结果并通知用户。
- 网络超时、连接中断或返回结果缺少 `reportId`：结果视为不确定，不自动重试；先通知用户人工检查发件箱，避免重复日志。
- 服务端明确证明未创建日志的临时错误：最多按 1、5、15 分钟重试三次，每次仍使用完全相同的快照。
- 已取得 `reportId` 但读回失败：不重提，只报告验证失败并请求人工检查。

## 修改与取消

用户在执行前说“不发送”“取消这次日报”或修改任一内容时，先定位并删除对应 Agent 定时任务。删除成功即取消本次发送；随后向用户确认任务名称或 ID 及原计划时间。

修改时只有在旧任务删除成功后，才能生成新预览并请求新的“确认提交”。不得直接编辑已确认任务中的正文后沿用旧确认。

任务已经开始运行或日志已经取得 `reportId` 时，删除任务不能撤回钉钉日志；应如实告知，并仅在用户另行要求且钉钉提供相应能力时处理已提交日志。
