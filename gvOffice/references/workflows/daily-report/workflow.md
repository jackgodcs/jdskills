# 日报工作流

用户以 `日报：` / `日报:` / `日志：` / `日志:` 开始新请求时进入本工作流。进入后先执行 [运行环境门禁](../../shared/runtime-gate.md)，再读取 [钉钉日志集成](dingtalk.md)。

## 整理与预览

1. 运行 `daily-report setup` 检查模板配置。首次使用且用户尚未选择过模板时，默认推荐并展示“日报”（ID `14eade35f619cdbcee39df04266a2811`）、真实字段和其它候选，并使用该模板继续预览。
   - 用户选择其它模板后保存其选择，后续不得由默认模板或最近日志覆盖。
   - 默认模板不可用时，才尝试唯一匹配最近日志模板；仍无法匹配时列出全部候选等待选择。
   - 返回 `selectionRequired=true` 时停止预览，等待用户选择后用 `daily-report template-select --template-id <ID>` 保存。
   - 已配置模板仍存在时读取真实字段；模板被删除时重新进入上述选择流程。字段发生变化时按最新字段生成预览并明确指出变化。
   - 模板初始化只更新模板 ID、名称、来源和字段，不从最近日志推断接收人，也不得改写已确认的接收人配置。
2. 第一次写日报且尚未配置发送策略时，必须展示并要求用户明确选择：`immediate`（推荐，确认后立即提交）、`specified`（每篇指定完整 `YYYY-MM-DD HH:mm`）、`rule-based`（当天21:29；历史日报21:15前确认则当天21:29，之后确认则15分钟后；未来日报对应日期21:29）。不能自动落盘推荐项。配置后默认沿用，只有用户主动修改才重新预览和确认。
3. 从用户描述识别日志日期；未写日期时使用 `Asia/Shanghai` 的今天。一次包含多个日期时拆成独立日志。
4. 只使用用户提供、能直接推导或按下述规则明确继承的事实，按模板字段整理。不得编造缺失内容。
   - 用户本次提供了“近期需完成工作”时，完全使用本次输入。
   - 用户明确表示该字段“无”“暂无”“没有”或要求留空时，视为本次明确输入，不继承历史内容。
   - 用户本次完全没有提供该字段时，运行 `daily-report defaults`，从当前配置模板的最近一次已提交日志继承非空的“近期需完成工作”。
   - 继承值只用于本次预览，不写入长期配置。预览中必须标注“继承自上次日志”，并允许用户修改、清空或替换。
   - 没有同模板历史日志、历史字段为空或读取失败时不继承，仍把该字段列为缺失项。
5. 输出完整预览，单列缺失字段，并显示日志日期、接收人、模板、发送策略和本篇实际发送时间。
6. 用户补充后重新输出完整预览，直到用户明确回复“确认提交”。统一确认可以覆盖多份预览，但每个日期建立独立计划，便于分别取消。

`rule-based` 的预计时间由 `daily-report schedule` 计算：

- 过去日期：最终确认时间早于 21:15 时，当天 21:29；否则确认后 15 分钟。
- 当天日期：最终确认时间早于 21:29 时，当天 21:29；否则确认后 15 分钟。
- 未来日期：对应日期 21:29。

## 发送

默认“日报”运行 `daily-report contents` 构造已验证的固定字段顺序，图片和附件无内容时省略。提交后必须取得 `reportId` 并回读日期、正文和顺序；失败时不得自动换参重试。定时提交仍使用一次性 [Agent 定时 fallback](agent-scheduled.md)。

本工作流的 Report 命令、模板字段和回读契约已经固化。日常生成预览、立即提交、定时提交和发送结果核对均直接执行本 reference，不重复查询 DWS 文档、Schema 或 Help。契约外错误停止并报告；只有用户要求开发或修订日报实现时才重新核查能力。

发送前运行 `daily-report delivery-resolve`。`specified` 与 `rule-based` 都由 gvOffice/Agent 创建一次性定时任务，不得称为钉钉原生定时发送。

修改已安排日志时先取消旧计划，再重新预览和确认。Agent fallback 在执行前删除对应定时任务即取消；删除成功前不得创建替代任务。

接收人使用用户维护的完整配置列表，不假定只有某一个默认接收人。模板识别、切换和字段刷新必须原样保留该列表。增加、删除或整体替换接收人时先展示当前列表和目标列表，得到单独确认后再执行；稳定 userId 必须来自当前组织，不从姓名猜 ID。
