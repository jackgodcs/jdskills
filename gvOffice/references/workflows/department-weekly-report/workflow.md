# 部门周报工作流

用户以 `部门周报：` / `部门周报:` 开始请求，或明确要求“总结本周部门周报”时进入。先执行 [运行环境门禁](../../shared/runtime-gate.md)，再运行：

~~~text
node scripts/gv-office.js department-weekly-report inspect [--date YYYY-MM-DD]
~~~

未指定日期时使用 `Asia/Shanghai` 的当天；指定日期或日期范围时选择包含该日期的工作总结周期。脚本按表头实际日期跨月、跨年检索，找到总结列后只取右侧相邻的工作计划列。零命中、多命中或相邻列类型错误时停止，不猜测。

## 配置与定位

- 配置位于 `%LOCALAPPDATA%\gvOffice\workflows\department-weekly-report.json`，按当前组织使用。
- 源表保存快捷入口链接/ID和解析后的在线表格 `nodeId`；模板、目标文件夹保存链接与 `nodeId`。运行时优先使用稳定 ID，不依赖名称。ID 失效、类型改变或组织不匹配时停止并引导重新绑定。
- 每次成功创建后用 `target-record` 保存“周期结束日 → 生成文档 nodeId/链接”映射。后续即使人工改名，也更新原文档并保留现有标题。
- 模板每次从钉钉重新读取，不在 Skill 中固化副本；主持人首次从模板读取并保存为工作流配置，后续可调整。

## 数据完整性

`inspect` 返回周期、人员原始总结/计划、参会人、异常和已记录目标。Agent 不要先生成大段预览。

- 本周总结或下周计划为空、内容明显中断、周期不唯一或事实存在歧义时，本次停止，不新建或覆盖。
- 只列出具体人员、字段、原因和 `sourceEntry` 原始表格入口，让用户回源核对后重新触发。
- 用户可以针对当前异常快照明确回复“确认无误，继续生成”，用于请假或确实无工作内容等情况。源数据、目标周期或异常集合变化后必须重新核对。
- 强制放行时不在正式周报写“未填写”“待确认”“请假”等推测性占位。总结为空者不进入参会人员和总结；总结非空但计划为空者保留总结，不生成其计划。只有用户明确说明仍参会时才额外加入参会人员。
- 全员本周总结为空或找不到周期时不允许强制放行。

## 内容整理

每次读取最新 MLS 模板完整 JSONML，保持其在线表格、合并单元格、字体、边框和页面样式。只修改本工作流管理的正文：

- 标题为 `地图产品线周例会YYYYMMDD`，正文日期为 `YYYY.MM.DD`；日期取工作总结周期结束日。
- 主持人沿用配置；参会人员来自本周总结非空人员并排除主持人。
- 周工作总结先按真实内容归纳部门级主题，再保留全部非空个人明细。
- 后续工作计划先归纳部门级计划，再保留全部非空个人计划。
- 重要事项仅从“待处理、待联调、未完成、阻塞、问题、风险”等明确表述提取；只有原文存在明确方案才写方案。无明确事项时写“暂无”。
- 可统一编号、标点和明显错别字，允许合并重复表达；不得虚构进度、完成状态、解决方案或工作内容。

## 在线写入

数据完整时无需预览确认，直接执行：

1. 若配置已有该周期目标，先按 `nodeId` 验证它仍为可编辑 `adoc`，读取最新模板 JSONML和目标 revision，在目标上用 JSONML `overwrite` 完整重建正文。保留 `nodeId`、链接、评论、历史版本和人工改名后的标题。
2. 若没有映射，在目标文件夹按标准标题精确查找；唯一命中时接管并记录，多条同名时停止。零命中时用 `dws doc +copy` 将模板复制到目标文件夹，重命名为标准标题，再写入正文。
3. JSONML 覆盖使用读取所得 revision 做并发检查。复制模板或完整保留样式不可用时停止，不降级为无格式 Markdown/纯文本。
4. 写后重新 `doc +fetch --detail full`，验证标题/正文日期、人员和关键章节，并用 `target-record` 记录真实目标。回执说明取数周期、源列、新建或覆盖、文档链接及异常强制放行情况。

Doc、Drive 和 Sheet 调用契约已经固化。日常取数、生成、覆盖和结果回读直接按本 reference 执行，不在每次生成部门周报时重新查询 DWS 文档、Schema 或 Help。契约外错误停止并报告；只有用户要求开发或修订部门周报实现时才重新核查能力。该工作流的“数据完整时直接生成”是用户对正常路径的持续授权；目标、组织、模板或周期无法验证时不得扩张授权。
