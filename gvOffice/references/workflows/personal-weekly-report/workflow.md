# 个人周报工作流

用户以 `个人周报：` / `个人周报:` 开始请求，或明确要求根据本人的日报填写共享部门周报表时进入。先执行 [运行环境门禁](../../shared/runtime-gate.md)。首次使用运行 `personal-weekly-report setup`，复用个人日报的模板配置和部门周报的共享表格链接/真实 Sheet ID；资源按 URL 与稳定 ID 跟踪，不依赖名称。

## 只读检查与预览

运行：

~~~text
node scripts/gv-office.js personal-weekly-report inspect [--date YYYY-MM-DD]
~~~

- 未指定日期时使用 `Asia/Shanghai` 的当天。优先复用表格已有的、包含该日期的总结周期；没有时默认周一至周日。执行通常在周五，但提前执行允许生成截至当天的阶段总结并明确提示。
- 周期所属工作表按总结周期开始日期确定。已有列完全沿用；缺列时计划按日期顺序插入“工作总结”及其右侧“下周工作计划”。
- 日报只读取当前个人日报模板，按目标周期涉及月份分成不超过 20 天的窗口查询发件箱，再按正文 `日期` 精确筛选并按 `reportId` 去重。
- “本周工作总结”只使用 `今日完成工作`。`近期需完成工作` 默认不作为已完成或下周计划；只有用户明确要求时才用于下周计划。`需协调工作` 只在预览中提示，不自动写入表格。
- 周一至执行日的每个工作日至少要有一篇有效日报。同日多篇合并。缺失时停止并列日期；用户可说明请假、节假日或无需填写后强制放行当前快照，也可直接补充当天工作内容作为临时汇总材料。
- 当前 DWS 无法读取钉钉原生定时、尚未发送的日报。今天缺失时明确提示用户补充或待发送后重试，不静默生成不完整结果。

Agent 根据返回的 `reports[].completed` 按项目/版本/主题归纳编号列表，合并重复事项，保留版本号、量化信息和明确进度，不把计划改写成完成、不虚构事实。预览只显示目标周期、纳入及缺失日期、最终总结、用户提供的计划、结构变更摘要和覆盖影响。

## 表格结构保护

- 目标表格链接来自共享配置；最终回执优先返回“我的文档/周报”快捷入口。
- 没有目标月份工作表时，复制最近结构有效的月份工作表，保留全部人员 Mention、列宽、冻结和样式。在这个尚未交付的新副本初始化过程中，可以清空旧工作内容、删除旧周期列，只保留 A 列，并创建当前总结列和右侧计划列。
- 新副本完成并回读验证后即视为已有用户资源；之后不删除工作表、行或列，不清空其他人员或非目标周期内容。只允许新增缺失结构及修改本人已确认的目标单元格。
- 已有工作表缺少周期列时按时间顺序插入；只有一列时补齐相邻缺失列。重复周期、重叠周期或顺序异常时停止，不重排。
- 本人行优先按当前 Profile 稳定 `userId` 对应 Mention 定位；读取结果无 ID 时要求 `@姓名` 唯一。缺行时追加并优先写 Mention，能力不足时写 `@姓名` 文本并说明。同名多行停止。
- 新列继承相邻同类型列的样式和自动换行，不复制成员内容。

## 确认和写入

个人周报必须先预览，用户明确回复“确认写入”后才执行结构创建和本人单元格更新。结构创建和内容写入共用一次确认：

- 写入前重新读取工作表结构和目标单元格；任一内容或结构与预览快照变化时停止并重新预览。
- 本次未提供下周计划时，计划单元格保持原样，不清空、不自动推导。
- 本次明确提供计划时，预览旧值和新值，确认后完整覆盖计划单元格。
- 同周期重复运行重新汇总日报，确认后完整覆盖本人总结单元格，禁止追加造成重复。
- 单元格写入纯文本编号列表，每项一行，不含 Markdown、日期标题或日报链接；保留/继承自动换行和样式。
- 写后只回读本人目标单元格和关键结构，验证成功后返回快捷入口及可用的目标工作表直达链接。

写操作按当前 `dingtalk-misc` Sheet reference 的精确 DWS 契约执行。初始化新副本失败时，只有能证明它由本次任务创建、尚未交付且无用户编辑才可删除；否则保留并报告真实状态。
